# Meshers project review | 17 November 2026

**Put the next development effort into measuring the physical domain and the FE solution on the mesh the user actually receives.** Meshers already has credible results on periodic implicit solids, a release benchmark history that preserves failures, and an unusually extensive Microgen comparison. The largest risk is accepting a fast, well-shaped mesh of the wrong domain. The next is spending fewer elements to compute a different stiffness. Both occur in the evidence below.

## Progress on the first three changes

[PR #9](https://github.com/kmarchais/meshers/pull/9) implements the controls below. The solver measurements used the released 0.2.1 wheel. The findings about that release remain dated to the original review.

## What to tackle next

1. **Geometry admission now has three measured wheel cases.** All passed the sampled audit. Uniform Gyroid came closest to the 0.002 boundary cutoff with a forward upper bound of 0.001930. The release benchmark records the per-class measurements, component volumes and worst locations. [Geometry results and replay](../demos/solver/release-wheel/geometry-admission.md)

   Original acceptance criteria. Use an independent sampler on the intended boundary and the exported mesh. Report both directions of distance for each relevant wall or cap, signed volume, component coverage and periodic face pairing. Publish the sampling density, reference uncertainty and worst location. For this unit-cell study, use the frozen cutoffs of 0.002 sampled boundary distance, 1% relative volume error and 0.1 minimum quality. Include a deliberately missing patch or component that the audit must reject. Keep every failed case in the results.
2. **Measure cost at matched physical error against live Microgen.** Replay the default and explicitly tuned VTK/MMG routes alongside Meshers on the same host. Charge geometry construction, conversion, repair, assembly and solve. Use a refinement series and an independently converged reference to bracket the declared stiffness tolerance. Report a defined local stress quantity as a second outcome. Publish repeated timings, free DOFs and failures for each route, plus any target that a route could not reach within budget.
3. **Use those results to pick the next optimization.** If geometry fails, fix the boundary class shown by the audit. If the solve dominates at the target, compare FE-guided Tet4 sizing with curved Tet10. If generation dominates, profile field evaluation and adaptation on the admitted case. Freeze the candidate settings, then replay an unseen phase or thickness. Change a default only when the held-out result lowers total cost at the declared error and preserves the geometry checks.

## Findings that affect acceptance

### 1. A mapped cap can exceed tolerance while the mesh reports zero error

On the published Windows 0.2.1 wheel, this call returned 189 nodes, 768 tets, volume 1.0000000000000002 and `sampled_surface_error == 0`.

```python
mesh = meshers.generate_intersection(
    {"a": lambda x, y, z: 0 * x - 1, "b": lambda x, y, z: 0 * y - 2},
    coordinate_map=lambda u, v, w: (u, v, w + u * u),
    cells=4,
    optimize_passes=0,
    snap=0,
    geometry_tolerance=1e-4,
)
```

The bottom cap is the graph `z = x²`. Its straight edges miss that graph by as much as 0.015625 vertically at their midpoints. Since its slope is at most 2 on the box, the distance to the exact cap there is at least 0.015625/√5, over **69 times** the requested tolerance. The top and bottom have the same bias, so total volume is almost exact. The checker selects triangles whose vertices share a named constraint bit. Neither constant constraint labels the curved chart caps. This matters for pressure loads, contact and wall thickness even when a volume check passes.

Measure mapped faces and edges in physical coordinates. For each face class report sample count, maximum and a witness location. Give an unmeasured class an explicit status. Keep this manufactured map as a regression with known chord error. [Boundary selection and distance checks](https://github.com/kmarchais/meshers/blob/67de95ce1c9b522b85f11cd258830bc744bac562/crates/meshers-python/python/meshers/intersection.py#L245)

### 2. A disappearing component can look like a perfect empty result

A sphere of radius 0.06 in the unit cube has volume 0.000904779. With a squared-distance field negative inside, four cells per axis, zero snap, zero optimization passes and tolerance 0.02, the 0.2.1 wheel produced 24 tets at center (0.125, 0.125, 0.125). Moving the center to (0.125, 0.125, 0.25) produced zero tets and zero reported error. The field and lattice missed each other. The first position already underestimated volume by about 36%.

The project documents the sampling limit. Its practical consequence is that a validator sampling only mesh faces has no witness for a missing island or ligament. Include fixtures with known component counts, voids, through-holes and load paths. Sweep phase at fixed feature-size-to-spacing ratio. Record the smallest resolved feature and the failure rate. Where the user supplies no feature bound, distinguish a sampled-empty result from an analytically empty domain. A separate API edge case appeared in the same probes: requesting `order=2` for an empty solid returned connectivity shapes `(0,4)` and `(0,3)`; the documented quadratic widths are 10 and 6. Include empty output in solver/export round trips. [Sampling and clipping](https://github.com/kmarchais/meshers/blob/67de95ce1c9b522b85f11cd258830bc744bac562/crates/meshers-core/src/implicit.rs#L1738) · [Quadratic dispatch](https://github.com/kmarchais/meshers/blob/67de95ce1c9b522b85f11cd258830bc744bac562/crates/meshers-core/src/implicit.rs#L745) · [Python return contract](https://github.com/kmarchais/meshers/blob/67de95ce1c9b522b85f11cd258830bc744bac562/crates/meshers-python/python/meshers/__init__.py#L276)

### 3. Positive sampled Tet10 Jacobians can miss an interior fold

A ten-node tetrahedron can represent the map `X(r,s,t) = (r, (r−0.38)s, (r−0.42)t)` exactly. Its determinant is `(r−0.38)(r−0.42)`. Every probe in the core stencil and in the release gate sees a positive value. At `r = 0.40` the determinant is −0.0004. I passed the ten mapped reference nodes to the release gate's `cell_geometry`; it returned positive integrated volume 0.00993333. This is a constructed validator counterexample. It does not establish how often generated meshes fold.

Keep the cheap samples. Add a reference validator that bounds the determinant polynomial and subdivides ambiguous elements. Track valid, inverted and unresolved counts with the time spent establishing each. For geometry error, sample the final six-node faces against the original field in both directions. The release table explicitly reports linear-parent surface error and corner quality even on Tet10. Neither measures a change confined to midside nodes. Include straight and curved Tet10 on identical corner connectivity to isolate that change. [Core sampling stencil](https://github.com/kmarchais/meshers/blob/67de95ce1c9b522b85f11cd258830bc744bac562/crates/meshers-core/src/quadratic.rs#L40) · [Independent release calculation](https://github.com/kmarchais/meshers/blob/67de95ce1c9b522b85f11cd258830bc744bac562/tools/performance_gate.py#L36) · [Johnen, Remacle and Geuzaine on Jacobian bounds](https://orbi.uliege.be/handle/2268/128340)

### 4. Boundary fitting can leave quality diagnostics describing earlier coordinates

On the 0.2.1 wheel, fit the sphere `(x−0.5)²+(y−0.51)²+(z−0.52)²−0.35²` with a second, always-negative constraint, four cells, snap 0.2, zero optimization passes and tolerance 0.029945356001979177. The fitter accepted 18 vertex moves. Reported minimum MMG quality was **0.399460**. Recomputing it on the returned coordinates gave **0.393047**, an overstatement of 1.63%. The fitter checks incident tets against the requested floor. The caller refreshes sampled boundary error and volume, while the minimum MMG quality and count below 0.1 still come from the native mesh. That makes an optimization agent's reported quality improvement or loss unreliable on this path. Recompute these two values from the returned arrays after a successful move. Extend the existing annular regression, which already requires `geometry_vertex_moves > 0`, with independent assertions on both values. [Fit acceptance and diagnostic update](https://github.com/kmarchais/meshers/blob/67de95ce1c9b522b85f11cd258830bc744bac562/crates/meshers-python/python/meshers/intersection.py#L708) · [Annular test](https://github.com/kmarchais/meshers/blob/67de95ce1c9b522b85f11cd258830bc744bac562/crates/meshers-python/tests/test_intersection.py#L701)

### 5. The release gate protects reproducibility, but cannot score a new algorithm

The seven PR cases and eleven release cases use fresh paired processes, a warmup, five measured pairs, a single numerical thread and hashed binaries. A past failed quality run remains visible. Keep these controls. Three details matter to an agent proposing changes.

- The gate compares volume to the baseline mesh and reads boundary error from the candidate's own diagnostics. Agreement with the old mesh can preserve the same geometric error. The release's mapped fixture exercises an open sector. Add the closed annular seam, cap and fitting probes to the independent geometry checks.
- The independent topology check uses the supplied surface triangles. Two incidences per edge does not establish that this is the exterior of the returned tets. The periodic loop checks displacements of supplied pairs and can miss omitted pairs. Reconstruct exterior faces from tet incidence, then compare complete oriented caps, node bijections and, for quadratic cells, mid-edge identity. Test the validator by removing a face set or a periodic pair from a known-good result. The solver studies already contain stronger periodic checks.
- Using the release comparison function, a synthetic reduction from 50,000 to 45,000 tets with every other metric fixed failed the 1% count guard. Four surface errors of 0.001 and a fifth of 0.09 produced no comparative failure against a 0.001 baseline when all quality values stayed fixed. Quality has a per-repetition regression check; comparative surface error uses the median. Keep a fixed-output CI check, require each measured candidate to meet independent geometry limits, and use a separate experiment to rank valid reductions in cost.

### 6. Changing the worker count can change which geometry algorithm runs

The Python entry point selects native, compiled or callback evaluation. For eligible compiled fields it can also recover explicit planes or branch constraints, which helps preserve a box edge or cylinder rim. Its `scalar_mode` conditions include `threads != 1`, an explicit gradient, element order and band selection. Two workers can therefore change the representation as well as execution time. A one-thread/four-thread timing on such a case is ambiguous even if both calls succeed. The Rust retained-constraint path explicitly requires one worker in this configuration. Record the selected geometry route as well as the evaluator, and compare field-equivalent encodings across worker counts on the capped cylinder and box. Use an unchanged route for thread-scaling claims. [Python dispatch](https://github.com/kmarchais/meshers/blob/67de95ce1c9b522b85f11cd258830bc744bac562/crates/meshers-python/python/meshers/__init__.py#L337) · [Rust eligibility rules](https://github.com/kmarchais/meshers/blob/67de95ce1c9b522b85f11cd258830bc744bac562/crates/meshers-core/src/implicit.rs#L558) · [Capped-cylinder and box controls](https://github.com/kmarchais/meshers/blob/9d156a2982277aed3a28fbcaeb676cc8b7236ca9/PROJECT_TRACKING.md)

The documentation also makes the available routes difficult to discover. At the reviewed release revision, the top-level README introduces version 0.1 and the changelog stops at 0.1.0, while the Python package declares 0.2.1. Document which combinations of geometry, element order, periodicity, adaptation, feature flags and workers have a tested public entry point. Generate the examples from the installed wheel, including one supported and one intentionally unsupported combination. ## CAD, triangles, quads and hexes

**CAD already has two prototypes worth distinguishing.** In the preserved CAD branch, the tessellation/distance-field volume route lost 39.1% of the impeller solid. The input tessellation lost only 0.016%. The later direct trimmed-face mesher shares CAD-edge nodes, evaluates points on the CAD face and retains face IDs. Its impeller boundary enclosed volume was within about 0.024%, but the study did not recover that exact boundary in a conforming solid mesh. T106 failed a curve/surface agreement check. Those outcomes give the CAD roadmap a concrete first milestone. Preserve the direct surface's topology, shared edge and face IDs through tetrahedralization. Benchmark a plate with a hole under traction, the impeller solid, its surrounding fluid region and the open T106 faces against the same STEP geometry in Gmsh. Record per-face distances, trim-loop and hole counts, tagged pressure area and resultant, and per-region volume. A large surrounding fluid volume can hide an unacceptable blade error. [Earlier CAD volumes](https://github.com/kmarchais/meshers-legacy/blob/30192dfe687abe3262693678d55fff61ec74ef99/docs/site/cad-benchmark.md) · [Direct CAD faces](https://github.com/kmarchais/meshers-legacy/blob/30192dfe687abe3262693678d55fff61ec74ef99/docs/site/cad-direct.md)

A newer implicit CAD-union control helps choose what to fix first. Its Tet4 wall corners lay on the analytic wall to about 1e-13, yet the largest forward error fell inside a smooth curved patch. Curving the same 49,422 tets reduced nominal absolute volume error from 0.6961% to 0.0001082% while raising nodes from 10,147 to 72,793. Measure trim curves and face interiors separately. This result supports a curved-element experiment on a known analytic union; arbitrary imported STEP solids still need the boundary-recovery test above. [CAD intersection and curved geometry controls](https://github.com/kmarchais/meshers/blob/9d156a2982277aed3a28fbcaeb676cc8b7236ca9/PROJECT_TRACKING.md)

**Triangles have more evidence than quads for surface analysis.** A working-tree Gyroid comparison at about 25,000 nodes measured 2.577 s for direct triangles versus 3.958 s for the extracted tetrahedral boundary, with relative thermal-gradient errors of 3.88% and 4.09%. The study includes refinement and closed-surface heat conservation. These are scalar surface PDEs. Shell bending brings rotations, thickness, normals, locking and load transfer into the comparison. The quad prototype's 17.2× optimizer speedup used an identical pre-existing layout. Its fully native output had 99,824 quads and 1,045 irregular vertices versus 43,712 and 220 in the external layout. Benchmark direct quads against direct triangles on the same shell problem at matched error and free DOFs. Include warped quads and seams, and check the bilinear map before solving. Keep print/preview acceptance separate: watertightness, intersections, wall thickness and volume bias matter there. Local prototype sources in the reviewed working tree were `experiments/native-quads/THERMAL_VALIDATION.md` and `experiments/native-quads/README.md`.

**Hexes should start with a swept solid.** The reviewed release has no general hex-volume generator. Use a swept rectangular beam and a curved thick-walled sector with known topology. Test shared quad faces, boundary tags, orientation, interior Jacobian bounds and the chosen solver's node order. Run an affine patch and a bending refinement series. Compare Hex8 against Tet4 and curved Tet10 at the same displacement/energy error, reporting integration rule and any hourglass stabilization. Introduce a perforated or branching part next, with an explicit outcome when the sweep topology is unsupported. Record the fraction of hexes and the transition elements if a later method produces mixed cells. This sequence tests solver value before committing to general all-hex CAD meshing.

**Product boundary.** The release's stable volume API, feature-gated surface generator, research quad code and CAD archive have different entry points. Ordinary builds omit the Python `experimental-surfaces` feature. Add a feature-enabled source-build test for the surface route before treating it as a supported wheel capability. Adaptive extraction from a field or a validated background also differs from remeshing an arbitrary user's mesh with materials, point fields and boundary conditions. The remeshing benchmark above supplies a concrete contract for that extension. ## Original priorities from the release review

1. **Make wrong answers visible.** Add the mapped-cap, translated-component and folded-element controls to an independent validator. Fix stale post-fit diagnostics and check them against returned arrays. These are small fixtures with known answers, suitable for every PR.
2. **Publish one reproducible release-wheel comparison.** Start with the Gyroid Tet4 count/stiffness tradeoff and the admitted Schwarz control. Freeze the geometry and acceptance criteria. Put the exact Microgen route, references, baseline results, failures and replay command under version control. Add one unseen specimen before using the result to change defaults.
3. **Fund one optimization from the measured bottleneck.** If solving dominates, test FE-guided sizing against curved Tet10. If construction dominates, profile callback evaluation and adaptation. If geometry admission fails, fix the failing boundary first. Promote a change only when a fresh held-out run shows lower cost at the declared physical accuracy.
